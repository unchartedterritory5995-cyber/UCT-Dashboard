# The frozen certification corpus

⛔⛔ **DO NOT REGENERATE THESE FILES.** They are the exact pages every Wave P
quality number was measured on, and `P2-LINUX-OCR-VERSION-CERT` exists to
compare **one engine against another on the same pixels**. Regenerate them and
the comparison silently becomes "a different engine on different pages", which
is not a comparison at all.

⚰️ **This is not a precaution, it is a repair.** The first real run of
`.github/workflows/ocr-linux-cert.yml` generated the corpus inside the bookworm
container from `tools/wave_p_fixtures.py` — same script, same seeds, repo-owned
fonts — and **all eleven page images came out different** under that container's
Pillow/FreeType. The signature check refused, which is the only reason the run
did not publish a 5.3.0 recall number measured on pages nobody had ever
benchmarked.

⭐ **These bytes are provably the reference corpus.** Re-running the 5.4.0
benchmark against them reproduces `tools/wave_p_ocr_reference_5_4_0.json`
exactly — every CER, every financial-recall and every search-recall figure
identical, timings aside.

```
manifest.json    the ledger + per-page ground truth
*.pdf            10 fixtures, 15 pages, 11 of them page images an engine reads
```

⛔ **Synthetic, and only synthetic.** Generated by `tools/wave_p_fixtures.py`
from repo-tracked DejaVu fonts. No member Notebook document, no production note,
no customer content has ever been in this directory, and none may be added.

Verify with `python tools/wave_p_corpus_signature.py` (it defaults here).
