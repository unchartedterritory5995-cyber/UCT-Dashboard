# F-03b — Provider ledger (canonical)

**Vocabulary.** TERMINAL-CURRENT = the `/calendar` surface display-named "UCT Terminal" (route, keys, `/api/calendar/*` unchanged). TERMINAL-NEXT = the product this program designs. UT is the parent brand; UCT Intelligence is the product.

**Status ladder** (preamble, ascending): **KP** KEY-PRESENT (a credential NAME exists in configuration) → **CR** CODE-REFERENCED (code calls it; path cited) → **OC** OBSERVED-CALLED (a runtime artifact within 30 days; artifact cited) → **CA** CONTRACT-ACTIVE (owner-confirmed — **no row reaches CA**; no leaf saw a contract). Following D-03 §2's recommendation, every row also carries an **evidence class**: `code-only` · `config-recorded` (a Railway variable or armed flag, read 2026-09-02) · `dated-probe` (a dated live-probe note inside a module docstring — a CLAIM about a past run) · `live-read` (an admin endpoint or log read this week). A key in configuration is not evidence of use.

**Licensing classes** (E-02 §0, capped per this contract): **LA** Likely Allowed / verify contract · **R** Restricted on the face of a public clause · **U** Unknown · **X** Unsuitable (no purchasable remedy). Where E-02 classes a US-Government source **A** (Allowed — no vendor licence in the path), this ledger records **LA (E-02: A)** because the contract forbids anything above LA. Massive and FMP cells read `without / with` — Individual tier / Business tier for Massive, no-DDLA / DDLA for FMP.

**OI-04 default, as applied.** "Any key with no OBSERVED-CALLED evidence in 30 days is treated as retired." Applied literally, that would retire OpenAI, Perplexity, SnapTrade, Stripe, Zoom and YouTube — integrations that are code-referenced **and** armed by a Railway flag the owner can see. This ledger therefore applies the default to rows whose strongest evidence is **KEY-PRESENT or code-only with no arming flag** (Bullflow, Polygon-direct, Unusual Whales on the dashboard side, `HF_TOKEN`, `VERCEL_*`, Webshare) and marks armed-but-unmeasured rows **ARMED · OC NOT DETERMINED**, naming the single read that would settle each. The owner should confirm that reading (§7, Q-A).

## 0. HEADLINE

**Data classes with NO provider at all:** Level 2 / order book · corporate credit and bond quotes (FRED is the only fixed-income series source and it is keyless) · FX and crypto **bars** (snapshot-only) · whisper numbers · a consensus-revision timeline · **short-interest history** (current short interest is single-sourced to a nightly, sparse Finviz export with no terms document) · analyst-level (per-broker) estimates.

**Evidence ceiling in one line.** From a **dashboard-side production artifact**, only **FMP (🟢) and Finnhub (🟡)** reach OBSERVED-CALLED — the provider-coverage monitor's 06:08 UTC cycle on 2026-09-02. **Massive, Finviz Elite and yfinance** reach it from **engine-side logs on the owner's PC** (scanner 2026-08-31/09-01, breadth collector 2026-09-01). Everything else is KEY-PRESENT + CODE-REFERENCED, some with an armed flag, none with a log line. Nothing is CONTRACT-ACTIVE.

**INTERPRETATION.** The stack is Massive-centred (bars, quotes, movers, snapshots, chains, OPRA tape, dark pool, splits/dividends, news, flat files — 20 of 29 derived products, E-04 §2) with FMP as the fundamentals/estimates/calendar spine, and a long tail of legacy, duplicate and dormant keys that nobody has retired because a key that must stay unset is not a decision anyone can see in code (D-03 §3.1). The licensing column is decided by two owner facts — the Massive tier and the FMP DDLA — not by anything a leaf could read.

**RELEVANCE TO UCT.** TERMINAL-NEXT inherits ~40 scheduled provider touches on a single-process web pod with only two call budgets (Finnhub 60/min, AlphaVantage 25/day), one true provider abstraction (Stripe), and a vendor concentration risk that is also its licensing pivot. The ledger's job is to make every row's next action a one-line owner answer or a one-line engineering change.
