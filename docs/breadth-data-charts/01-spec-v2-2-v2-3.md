## 1. V2-2 — stacked panels

Roadmap row, verbatim (`01-audit.md:372`):

> | 7 | **V2-2 — stacked panels** | A-05, magnitude split, metric-attached lines per panel, log scale, sticky colours, end labels | V2 |

### 1.1 A-05 — the defect it fixes

`01-audit.md:70-76`, verbatim:

> ### A-05 · Dual-axis charts invent relationships — P1 · V2
> **Finding.** 10 of 36 presets, and any hand-picked selection spanning two families, overlay two unrelated
> scales: Volume Thrust's parity (ratio 1.0) sits exactly on Net Advancers −500 and the lines "cross" wherever
> the axes happen to align. A third family is folded into the right axis (`VIX / ratio`).
> **Evidence.** F-8; `preset-volume-thrust__1280`, `mixed-family__*`; dataviz anti-pattern #1.
> **Fix.** See [Y axes — the recommendation](#y-axes--the-recommendation): stacked panels, one per unit
> family, shared X, linked crosshair and zoom.

⭐ This is the **#1 charting mistake** in the `dataviz` skill's own words ("Never a dual-axis
chart… Two measures of different scale -> two charts, small multiples, or indexed to a common
base"). The fix is not a tweak to the existing chart; it is a different chart.

### 1.2 The build

| # | Item | Requirement |
|---|---|---|
| **W2-0** | palette + styling | The first drawn pixels, so the theme arrives here. Tokens per the theme-island rule: any `--dc-*` custom property with a `[data-theme]` variant must be pinned in EVERY island or `styles/themeIslands.test.js` fails by name. |
| **W2-1** | panel split by unit family | One panel per unit family, derived from the registry — never a hand-typed family list. **The table test is the authority**: the split a reader computes from the metric table and the split the chart draws must be the same set. |
| **W2-2** | shared X, linked crosshair + zoom | One x-scale across panels; a crosshair in one panel reads all of them. Per `dataviz`: an interactive chart ships the hover layer by default. |
| **W2-3** | metric-attached reference lines | Lines belong to the metric, drawn in ITS panel — not a global overlay that lands on whichever axis happens to be underneath. ⚠️ `refLines` is NOT in the registry (§0.2); either it is added here or the lines are declared locally and the gap recorded. |
| **W2-4** | log toggle | Per-panel, off by default. A log axis with a non-positive value present must refuse and say so, never silently drop points. |
| **W2-5** | sticky colours | ⛔ **Colour follows the ENTITY, never its rank.** One map, so a filter that changes the series count must not repaint the survivors. **Shuffle rail**: reorder the selection, assert every key keeps its colour. |
| **W2-6** | end labels | Direct labels at the series end for ≤4 series; a legend is always present for ≥2. Never a number on every point. |
| **W2-7** | Time Navigator byte-identical | The existing navigator is not this increment's to change — a golden holds it. |

⛔ **Magnitude split consumes `chartMagnitude.js` (§0.3).** It is the already-shipped runtime
rule; V2-2 reads it to decide the split and does not restate `MAGNITUDE_LIMIT`.

### 2.2 A-11 — long history, and why it is not just a bigger number

`01-audit.md:119-126`, verbatim:

> ### A-11 · Seventeen years of history are stored and unreachable — P1 · B + V2
> **Finding.** History reaches 2008-01-02; the tab asks for 365 rows (to 2025-03-31). Simply asking for more

> **Evidence.** F-15; §1 History.
> **Fix.** See [Long history](#long-history--the-recommendation).

⛔ **"via B1"** in the roadmap row is load-bearing: the fix is the `/series` route (which
exists — `api/routers/breadth_monitor.py:736`), **not** raising `days=` on the old one. The

⚠️ **Q4 remains open and is not resolved by this spec:** whether `/series` is fast enough at

### 2.3 LTTB

Downsampling for long spans, above a **measured** threshold — not a guessed one. The `/series`
contract already names `sampling: 'lttb'` (`01-audit.md:305`). ⛔ The rail must prove the
sampled series preserves the extremes a reader would act on; an LTTB that clips a spike is
worse than no chart, because it looks authoritative.

### 2.4 The era note — ⭐ Q3, RESOLVED

The roadmap's "era note" (`01-audit.md:373`) is the **Era comparability** bullet at
`01-audit.md:309-311`, verbatim:

> - **Era comparability.** When the window's `universe_count` changes by more than 20 % end to end, count panels
>   show "Counts depend on the measured universe (1,521 → 2,648 names); % versions compare across years" with a
>   one-tap swap to the ratio metric where one exists (`hi_ratio`, `lo_ratio`).

Design restatement, `docs/breadth/02-design.md:258`:

> | Range crosses universe growth > 20 % on a count panel | panel note *"Counts depend on the measured universe (1.5k → 2.6k names). The % versions compare across years."* with a **Use %** action | — |

⚠️ **The two wordings differ** (`1,521 → 2,648` vs `1.5k → 2.6k`; semicolon vs two sentences).
The audit is the authority. ⛔ The numbers in both are ILLUSTRATIVE — the real pair is computed
from the window's own `universe_count`, and hard-coding either pair would be the
second-authority defect.

**Consequence for the request:** `universe_count` must be among the ≤8 requested keys whenever
a count panel is on screen, or the note cannot be computed. That is a client-side requirement,
not a wire change.

## 2.7 ⛔⛔ THE FLIP NEEDS THREE VARIABLES, IN ORDER — not two

Measured 2026-09-17, and it changes DC-2 §5's procedure.

The V2 tab's entire read path is `useBreadthSeries` → `GET /api/breadth-monitor/series`.
That route is **dark**: `api/routers/breadth_monitor.py:699` refuses unless
`BREADTH_SERIES_ENDPOINT_ENABLED` is truthy, and the ledger row confirms
`status: dark`. ⭐ The flag dependency is declared BEFORE `require_paid`, and FastAPI
resolves in declaration order, so it is **404 for every caller class** — a paid member
included. It is not a soft degradation.

So turning on `BREADTH_DC_V2_2_ENABLED` alone does not ship a chart. It ships the V2
shell rendering its honest error — *"Series unavailable (404)"* — to whoever got the
flip. The surface would be live, member-visible, and broken, and every check that asks
"did the flag reach the payload?" would say yes.

**The order is forced, and it is the safe one:**

| # | | why this order |
|---|---|---|
| 1 | `BREADTH_SERIES_ENDPOINT_ENABLED=1` on `web` | ⭐ Turning the READ PATH on first is invisible to members — nothing calls it while both DC flags are off. The reverse order is member-visible breakage. |
| 2 | verify `/series` answers 200 **from the pod**, not from `--kv` | `--kv` shows what the service is configured with, which is not evidence the process has it. |
| 3 | `BREADTH_DC_V2_2_ENABLED=admin` (then `V2_3`) | the owner preview, on a read path already proven live |
| 4 | widen to `1` per increment, separately | they are independent and reverted separately |

⚠️ **And a `--set` is a RESTART either way**, whose behaviour this repo has measured
BOTH ways — so each step verifies a NEW BOOT and reads the value in-process.

⛔ **Rollback is not symmetric.** Unsetting a DC flag returns the tab to V1 on the
member's next authenticated request. Unsetting the series flag while a DC flag is still
on would leave V2 live and broken — so the series endpoint is turned OFF **last**, if at
all, and never as the first move in an incident. H15's "roll back first" means the DC
flag, which is the one that actually hides the surface.

## 4. Standing constraints that bind every item above

- **Colour follows the entity, never its rank** (W2-5), and categorical hues are assigned in
  fixed order, never cycled.
- **One axis per panel.** The whole increment exists because two scales in one frame invent a
  relationship.
- **A rail that shells out carries a non-vacuity control**, and its mutation proof runs before
  the rail is called done.
- **Assert user-facing copy by RENDERED TEXT**, never by state — the coverage language IS the
  product here, and a correct state transition with blank copy is the failure this repo has
  shipped twice.
