## 1. Transcript passage -> cited excerpt (G1)

A call-transcript passage becomes the **same** Wave J/L object a PDF or web passage becomes
(`web_capture.py`:106-115 precedent; G-116..G-120), never a special case:

* One `j2_note_documents` row per `(note, symbol, quarter)`, identity
  `transcript:fmp:<SYM>:<YYYY>Q<q>`, `source_kind="web"`, `capture_type="web_passage"` — it never
  opens the PDF viewer, and Ask's coverage for it stays passage-only.
* One page per quoted **speaker turn** (`page_number` = the turn number; the text is the
  transcript's own `"Speaker: words"` form).
* `notes.create_excerpt` + `notes.append_document_excerpt` place the node and land the note's
  revision (`settleNoteWrite`) — no second writer.
* **The quote is re-verified against the held transcript only** (whitespace forgiven, nothing
  else). A mismatch refuses honestly and writes nothing; it never falls through to the
  AlphaVantage transcript route (`earnings_intel.py`:262-278). Mutation-proved (M1, M6, M7).
* Read-only on the transcript side: the FMP transcript cache and the stored
  `transcript_index.db`. Never `fmp_transcripts.get_transcript` (fetches on a miss), never
  `av_transcripts` / `alphavantage_client`. An AST import-graph walk with a control is the rail,
  plus a runtime trap on both fetchers (M1).
* Two doors, both lazy-loading the sheet (`SaveTranscriptPassage.jsx` loads only when a door is
  used, so neither the Notebook's first open nor the research workspace carries it):
  `SaveTranscriptButton` (destination picker + "a new note", or — handed no `notes` prop, as the
  calendar panel does — asks the server for the member's own notes on that ticker) and
  `TranscriptInsertHost` (the editor's `/transcript` slash item; the node lands at the caret,
  once per excerpt, mirroring the PDF "Save excerpt" idiom).
* Zero model calls.

## 2. Passed setups (G3)

`j2_passed_setups` (self-ensured, purged with the account): names the member **saved but did not
trade** — a scanner/Screener capture already sitting in one of their notes, a watchlist add
(`watchlist_items.added_at`), or a manual add — scored at +1/+5/+10/+20 sessions and the best move
within 20, from `bars.db` only (nothing fetched). Reference price and every horizon are **frozen
at save** (the close of the save day at/after 16:00 ET, else the prior stored session's close).

* A horizon with no bar is a **label**, never a number: `no_bars` (no stored bars for the
  ticker), `missing` (SPY's own stored sessions show the market has had that session and this
  ticker still doesn't), `pending` (the session hasn't happened), `unknown`. Mutation-proved
  (M3, M8 — the client renders the server's label, never `0.0%`).
* **Traded is decided before bars are even consulted** (the round-1 walk failure, fixed in
  `40d241e147`): a position opened from the save day through the 10th session — or already open
  across it — marks the name traded and removes it from the list, even when the store holds no
  bars for it at all. The original order checked `no_bars` first and could report a traded name
  as merely "no data".
* Saves from the last 60 days, capped at 300 rows a member. `GET` refreshes idempotently (M2);
  a nightly job (`notebook_passed_setups_nightly`, 17:40 ET weekdays, registered no-op while the
  flag is off) refreshes every member with a row. Zero model or vendor calls.
* Taken by `account_purge` (M4).

## 4. Decisions

1. **G2 is out of scope for 13G-1**, per the plan's own milestone ordering (13G-2/3 lands after
   13J). No thesis-chip code, stub or flag exists in this lane.
2. **The quote is re-verified against the cached transcript only, never re-fetched.** A miss is
   an honest refusal, never a trigger for the AlphaVantage fallback — the spec's explicit
   instruction, and the reason `transcript_capture.py` imports neither `fmp_transcripts` nor any
   AlphaVantage module (M1's rail).
3. **Traded-status for passed setups is computed before any bar lookup.** A name with zero stored
   bars that the member nonetheless traded must still leave the list; checking `no_bars` first
   would hide a real trade as a data gap (the round-1 walk failure).
4. **A missing horizon is always the server's label, never a client-synthesized zero** — both the
   backend (`missing: "no_bars" | "missing" | "pending" | "unknown"`) and the client renderer
   agree, and M8 mutation-proves the client side specifically.
5. **The TranscriptPanel.jsx mount stays a single, separable commit** so the controller can hold,
   drop or land it independently of the rest of the lane (ruling P2).
