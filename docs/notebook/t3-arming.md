## What merging does, before anything is armed

switch is unset.

   means OFF).
2. **Schema at boot, additive:** the `j2_note_checkins` projection table. The account purge deletes it, and the
   deletion manifest lists it.
3. **Sample notebook notes are left out of the check-in section of analytics** (`analytics._checkin_section`), as
   they already are everywhere else. No check-in can exist while the switch is off, so this changes nothing today.
4. **Copy doors reset a check-in's picks** (`trader_blocks.unpick_checkins`):
   - Duplicate, Save as template, every template read, and a style's outline all do this.
   - Import keeps them, because import is a restore.
   - Conflicted copies keep them, because they hold the member's own unsent version.
   - With no check-in in any note today, this is a no-op.
5. **`useBlockParams` also accepts a function of the latest params.** Every existing caller passes a plain object,
   so nothing changes for them.
6. **Shared helpers, behaviour unchanged for existing callers:**
   - `playbook_stats.get_playbook_stats(..., analytics_included=False)` is an opt-in argument;
   - `unified_coach.plain_account_id` is the one `'_all_'` translator.

   `railway redeploy --service web --yes`.

   `--kv`.
3. `/api/auth/me` for the smoke account carries `journal_tier3_enabled: true`.
4. As the smoke account, in its own Playwright context (never the owner's Chrome):
   - create a note, insert a check-in block, pick a mood and a focus, and let it save;
   - see the pick in Insights > Psychology > By check-in;
   - trash the note through the product (`DELETE`) and see the check-in leave the view.

   The smoke account ends with no note.
5. `GET /api/j2/insights/checklist-suggestions` answers 200 for the smoke account. A "too few winners" answer is a
   pass, because the account holds no trades.
6. `GET /api/j2/wrapped/<last year>` answers 200. `unavailableReason: no_trades` is a pass, for the same reason.
7. The app-wide client smoke (R-27): `python tools/hub_nav_smoke.py --auth`. Exit 0 is PASS, 1 a measured failure,
   2 INCONCLUSIVE. On a measured failure, apply H15: roll back first.
8. `docs/feature_flags.json`: move `JOURNAL_TIER3_ENABLED` to `armed` with the flip time, in the same docs push.

## Known limits, recorded rather than fixed

- **Pasting a single check-in block carries its picks** (OI-T3-1). A paste looks the same as a cut-and-move, and
  resetting on a move would wipe a real pick.
- **A re-imported duplicate keeps its picks** (R-T3-FIN-3). So re-picking on the copy records against the original
  day. A restore is expected to bring the days back.
- **A member's own tag outside the vocabulary can be suggested.** The member accepts each item themselves (spec
  item 15). Every negative emotion and mistake word is never suggested.
- **Thin samples are worded, not hidden.** For example, "too few to judge" behind a reveal, and "thin sample" beside
  a share line.
- **The walk's own refusals have no test** (OI-T3-2): a non-empty data dir, the shared root, a busy port. This is a
  dev tool's guard, not product.
