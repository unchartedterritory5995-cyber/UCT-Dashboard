## 1. What shipped (member-facing)

- **"Reporting soon"** — a list of the member's own names (positions, watchlist, flagged
  — explicitly **not** UCT20, "the firm's list, not the member's,"
  `earnings_prep.py:7-8`) that report within the next 7 calendar days
  (`WINDOW_DAYS = 7`, `:54`), sorted by report date then symbol. Each row carries the
  report date, before/after-market timing when the calendar has said so, which of the
  member's sets named it, and — if the member already drafted a prep note on that name in
  the last three weeks — a link to **Open** it instead of drafting a duplicate
  (`_existing_prep_notes`, `:268-278`, tag `earnings-prep`).
- **One-click draft** — `POST /api/j2/earnings-prep/{symbol}/draft` reads every fact a
  prep note opens with and hands them to the client, which writes them into a new note
  through the Notebook's own create door (`lib/earningsPrep.js` → `createNoteViaApi`,
  per the module docstring `:16-18`). **This module never creates a note itself** — R-12
  in the docstring names the reason: a second writer into notes is the thing this lane
  refuses to be.
- **The facts in a draft, each a cell carrying its source, its as-of, or why it is
  missing** (never a guess, `_cell`/`_missing`, `:143-150`):
  - **Report date + timing** — the UCT earnings calendar first, falling back to
    `earnings_intel.get_earnings`'s own `next_report_date` when the calendar has not
    named a day yet (`_report_cells`, `:322-335`).
  - **Expected move** — the options-implied move UCT captured the evening before the
    report (`implied_store.get_implied_history`), preferring that over the calendar's
    live overlay specifically because it is "the honest number: it was taken before the
    report" (`_expected_move_cell`, `:343-361`).
  - **Street numbers** — the coming quarter's consensus EPS/revenue against the same
    quarter a year ago, from `earnings_intel.get_earnings`'s `estimates`/`quarters`
    (`_street_cells`, `:364-399`).
  - **Reactions** — the last four reported quarters: beat/miss, surprise %, the
    earnings-day move, joined to whatever implied move UCT had captured ahead of that
    report (`_reactions_cell`, `:402-426`, `REACTIONS_LIMIT = 4`).
  - **Call recap** — **stored only.** `call_recap_store.get(sym)` is a SQLite
    point-read; `call_recap.get_call_recap` (which would warm on a miss and reach
    AlphaVantage transcripts and a model) is never called (`_recap_cell`, `:429-445`,
    docstring at `:430-432`).
  - **The member's own notes, trades and open position** on the name (and its known
    alias symbols, via `ticker_research.get_ticker_research_summary`), each capped —
    5 notes, 5 trades (`_member_cells`, `:448-490`).
- **The daily cap sentence**, shown when the 20th draft of the day is spent:
  *"You've drafted 20 earnings prep notes today, the daily limit. It resets at midnight
  Eastern."* (`CAP_SENTENCE`, `:64-65`, `cap_sentence()` `:537-538`).

## 2. The flag, the cost discipline, and reuse

`NOTEBOOK_EARNINGS_PREP_ENABLED` (`FLAG`, `earnings_prep.py:51`), unset = OFF, read per

`docs/feature_flags.json:1299`, `tools/notebook_switch_rehearsal.py:217`
(`"dark (wave 13 13C): Reporting soon on Research Home and a..."`), and the router's own
gate comment (`notebook_earnings_prep.py:10`: *"THE GATE IS A ROUTER DEPENDENCY:
`NOTEBOOK_EARNINGS_PREP_ENABLED` off answers the one 404"*). The commit `cdef34d18c`'s
own file list confirms the roster rows were added in the same commit:
`api/main.py`, `api/routers/auth.py`,
`app/src/pages/journal-2-0/lib/offline/notebookFlags.js`, `docs/feature_flags.json`,
`docs/notebook/security-review-notebook-routes.md`, `tests/test_notebook_flags.py`,
`tools/notebook_switch_rehearsal.py`.

The module's own rules, stated in its docstring (`earnings_prep.py:14-37`) and traceable
in the code:
1. **Never creates a note** — reads only.
2. **Reuse, never re-implement** — the window comes from
   `calendar_alerts.collect_earnings_window` (`_window`, `:195-216`, the same walk
   awareness and the watchlist already share); member sets from
   `calendar_personalization.get_user_ticker_sets` (`_member_sets`, `:245-265`); quarters,
   estimates and reactions from `earnings_intel.get_earnings`; the implied move from
   `implied_store`; the call recap from `call_recap_store`; notes from
   `ticker_research.get_ticker_research_summary`; trades and positions from the
   journal's own `list_trades_for_user` / `list_open_positions`.
3. **No AlphaVantage, no model call** — the module's docstring states the reason
   (AlphaVantage's 25/day budget is shared and this lane must not touch it) and names the
   rail: `tests/test_notebook_earnings_prep.py` (import graph + a runtime trap).
4. **Missing is said, never invented** — every `_missing(...)` call carries one of the
   named sentences (`MISSING_DATE`, `MISSING_TIMING`, `MISSING_MOVE`, `MISSING_ESTIMATES`,
   `MISSING_YEAR_AGO`, `MISSING_REACTIONS`, `MISSING_RECAP`, `MISSING_NOTES`,
   `MISSING_TRADES`, `MISSING_POSITION`, or `UNREADABLE` when a source itself failed,
   `:89-101`).
5. **20 drafts a member a day, durable** — counted in `daily_usage_counters` by the
   router (not this module), so a deploy does not reset the cap.

**Zero model calls, zero AlphaVantage calls** is also the ruling's own cost line
(`WAVE-13-PLAN.md` Appendix A.13C). Every read above is a cache or a store lookup; the
only network-shaped calls are the shared-cache reads other Notebook/calendar features
already make.

## 3. Routes

`api/routers/notebook_earnings_prep.py` (82 lines), `router = APIRouter(prefix="/api/j2/earnings-prep", ...)`.
Gate: `dependencies=[Depends(_require_enabled)]` at router level, checking
`prep.enabled()` — an off flag answers 404 before the session or the body is read, per
the router's own docstring (`:10`).

| method | path | answers | gate beyond the flag |
|---|---|---|---|
| GET | `/api/j2/earnings-prep/soon` | `reporting_soon(user_id)` | member, paid (`require_paid`, 402 `"Earnings prep requires a paid plan"`) |
| POST | `/api/j2/earnings-prep/{symbol}/draft` | `draft(user_id, symbol)` | member, paid; **daily cap** |

The cap mechanism: `daily_counters.Charge(prep.DAILY_SCOPE, str(user["id"]), 1,
prep.daily_cap())` then `daily_counters.take(...)`; a non-`None` return means the cap
was already spent and answers 429 with `prep.cap_sentence()`. `daily_counters.give_back(...)`
is called on any exception raised from `prep.draft(...)`, so a failed draft never
permanently costs the member a slot. `DAILY_SCOPE = "notebook_earnings_prep"`,
`DAILY_CAP_ENV = "NOTEBOOK_EARNINGS_PREP_DAILY_CAP"`, default 20
(`earnings_prep.py:61-65`, `daily_cap()` `:115-120`, reading the env var per call and
falling back to the default on a bad value).

## 4. No new database table

This lane owns no table of its own. `reporting_soon` and `draft` are pure reads over
caches and other features' own stores (`calendar_alerts`'s cache, `implied_store`,
`earnings_intel`, `call_recap_store`, `ticker_research`, `trades`, `positions`); the only
state this lane's own door writes is the note the member's own save path creates, tagged
`earnings-prep`, which is a `j2_notes` row like any other note. Not measured: whether
`j2_notes` deletion/purge handles an `earnings-prep`-tagged note any differently from any
other note — nothing in this lane's code suggests it does, and no evidence file was
found that tests it specifically.

## 5. A sandbox-only seam, and why it cannot leak into production

`SANDBOX_CALENDAR_ENV` (`NOTEBOOK_EARNINGS_PREP_SANDBOX_CALENDAR`, `:75`) lets the real
walk substitute a JSON file for the calendar window, because the walk's sandbox has
neither a live process-memory cache nor live vendors. `sandbox_calendar_active()`
(`:160-178`) requires **all three** of: the env var is set, `vendor_socket_guard.on_production()`
is false, and `conftest` (with its `SHARED_DATA_ENV_PINS` attribute) is already imported
into `sys.modules` — a condition only pytest and `scripts/hub_sandbox_boot.py` satisfy,
never the web pod. Not independently re-verified in this pass beyond reading the three
conditions in the source; cited as the code's own stated guarantee.

## 6. Decisions (the lane's own)

1. **UCT20 is deliberately excluded from "my reporting names."** `MEMBER_SOURCES =
   ("positions", "watchlist", "flagged")` (`:56-58`) — the firm's list is not "mine," per
   the controller ruling the docstring quotes.
2. **The call recap door is a point-read, never a trigger.** Reading `call_recap.get_call_recap`
   instead of `call_recap_store.get` would have made an earnings-prep draft capable of
   spending the shared AlphaVantage transcript budget and firing a model call — exactly
   what rule 3 above forbids. The store-only read is the structural enforcement of that
   rule, not just a comment.
3. **A draft is read-now, not cached-forward.** Every cell in `draft()` is computed at
   the moment of the call (`read_at = _now_iso()`, `:508`) and written into the note as
   plain text by the client — "the note keeps the values it was drafted with: nothing in
   a note re-reads a source" (module docstring `:11-12`). This is the same freeze
   philosophy 13A's plan grading uses, applied to a note body instead of a database row.
4. **One source failing never fails the draft.** Every external read in `draft()` is
   wrapped by `_safe(...)` with a named fallback (`:493-531`), so a dead `implied_store`
   or a broken `ticker_research` call degrades that one cell to `UNREADABLE` rather than
   taking down the whole response.
5. **Open positions are read through the journal's own reader, not re-implemented** —
   this decision exists because of a real bug the walk found (see §7).

## 7. A real bug the walk found, fixed in `4bf118fc5d`

The first walk (`bfcde2883b`) FAILED at its W1 step: a member's own open NVDA position
did not appear in the Reporting-soon list. The cause, documented in-file at the point of
the fix (`earnings_prep.py:249-254`): `member_interest._position_syms` selected columns
`sym` / `status = 'open'` from `j2_positions` — but that table has `symbol` / `closed_at`,
not those names. The query raised, was swallowed, and silently returned an empty set for
every member. The fix (commit `4bf118fc5d`) reads open positions through the journal's
own reader instead, `journal_two.positions.list_open_positions` (`_member_sets`,
`:255-260`), unioned into whatever `calendar_personalization.get_user_ticker_sets`
already returned for "positions" — "the union keeps this right whether or not that
reader is fixed later," per the in-file comment. This bug in `member_interest.py` is
explicitly **reported, not fixed, by this lane** ("not this lane's file," `:253`) — it
remains open in whatever module owns `member_interest.py`. A dedicated second mutation
proof, `M6-positions-from-shared-reader-only` (commit `327aab5d88`), exists specifically
to kill a regression back to the broken reader (§8).
