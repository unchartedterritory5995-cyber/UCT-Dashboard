## 1. The key and the row

`j2_entry_context` in auth.db, self-ensured by `entry_context.py`, purged with the account
(`account_purge._DIRECT_USER_TABLES`), key **(user_id, symbol, entry_day_et)**. The entry day is
`timeutil.compute_trading_day_et(entry_date)`, the journal's own ET-day spine applied to the
ENTRY timestamp (`j2_trades.trading_day_et` holds the exit day). Never a position id: a broker
trade's `position_id` is a sentinel `manual-<uuid>` (`trades.py`:773, :851).

A context, as every read returns it:

```json
{
  "symbol": "NVDA", "entryDay": "2026-10-02",
  "captureKind": "at_entry", "capturedLate": false, "captureDay": "2026-10-02",
  "capturedAt": "2026-10-02T14:31:07+00:00", "trigger": "manual_add", "version": 1,
  "fields": {
    "regime":   {"value": "amber", "source": "journal_two.regime.get_current_regime", "asOf": "2026-10-02", "missing": null, "detail": null},
    "rs_rank":  {"value": null, "source": "rs_ranking.get_rs_for_ticker", "asOf": null, "missing": "rs_cache_cold", "detail": null},
    "...": "one entry per FIELDS"
  },
  "why": {"text": "Tight flag at the 21EMA", "updatedAt": "2026-10-02T14:33:00+00:00"}
}
```

`captureKind` is `at_entry` (frozen on the entry day) or `captured_late` (the backfill froze the
market of `captureDay` for an older open position). **A reader that wants "the market at the
fill" (13F's regime-at-entry, held-into-earnings) must use `at_entry` rows only.**

## 3. When it freezes

Only while the flag is on, only for an entry whose ET day is TODAY, and once (INSERT OR IGNORE;
a row is never UPDATEd except its two why columns):

* **manual add** -- `POST /api/j2/positions` schedules `on_position_added` as a BackgroundTask
  after the position is written and returned; it never raises.
* **broker sync** -- an APScheduler listener on `broker_sync_due`, `broker_sync_warming`,
  `broker_sync_nightly_reconcile` and `broker_recent_orders_poll` (executed or errored) queues one
  `after_broker_sync` job. No broker or positions code is edited; the hook only READS
  `j2_positions` (open, `entry_estimated = 0`) and `j2_trades` (same-day round trips) and never
  raises.
* **sweep** -- the same function every 10 minutes, weekdays 09:04-16:54 ET, for any path the
  listener cannot see (a member's Sync now, a CSV import).
* **on demand** -- the position and trade routes freeze a today's entry that has no row yet.

A past day reads `not_captured` and is never reconstructed. A carried-in broker holding
(`entry_estimated = 1`, placeholder `entry_date`) reads `entry_day_unknown`.

## 4. The API (all paid, all 404 while the flag is off, before the session is read)

| route | answer |
|---|---|
| `GET /api/j2/entry-context/meta` | `{version, fields, missingReasons, notCaptured, captureKinds, whyMaxChars}` |
| `GET /api/j2/entry-context?symbol=&entryDay=` | `{status: captured / not_captured, key, context, reason}`; never captures |
| `GET /api/j2/entry-context/list?since=&until=&symbol=&limit=` | `{contexts, count}`, newest day first, at most 500 |
| `GET /api/j2/entry-context/position/{id}` | `{status: captured / not_captured / entry_day_unknown, key, context, reason}`; another member's id is the one 404 |
| `GET /api/j2/entry-context/trade/{id}` | the same, joined by the key (works for a sentinel position id) |
| `PUT /api/j2/entry-context/why` `{symbol, entryDay, text}` | `{context}`; empty text clears; over 500 chars 422; no row 409 |
| `POST /api/j2/entry-context/backfill` | `{backfill: {frozen, capturedLate, already, noEntryDay, deferred, failed}}`, at most 25 a call |

Python callers (13F, 13I-2) use the service directly: `get_context(uid, symbol, day)`,
`list_contexts(uid, since=, until=, symbol=)`, `contexts_for_trades(uid, trades)` (trades as the
journal serialises them: `id`, `symbol`, `entryDate`), `read_for(uid, "position" | "trade", id,
capture=False)`.
