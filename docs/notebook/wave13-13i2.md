## 3. Where the last agent stopped, and what this session found

The feature code (`46406462fb`, `5d40c39a57`) and its mutation proof (`93268cdb1e`, 11 of 11
rail mutations killed, `docs/notebook/evidence/wave13-13i2/mutation-5d40c39a57.txt`) were
already in on resume. The walk had actually **run** (contrary to the resume brief's belief that
it hadn't) at `ffbfb52123`/`94ea8ed875`, but the session that ran it hit the account weekly
limit before reading its own result — raw evidence sat committed, unread, with two real `FAIL`
rows (`walk-ffbfb52123/walk.json`): `W3_visual_playbook_filter_setup_and_rs_1200` and
`W5_phone_390`.

Reading both before touching anything (R-CITE):

* **W3 was the walk's OWN instrument, not the product.** `cards_api` correctly read `["AMD"]`
  (the backend's filtered answer was right). `cards_shown` read `["No"]`. Every card the walk
  seeds has no archived image — the seed writes `ta.fingerprint` directly into the note body,
  never through the freeze route that produces one (`plan_body()`, by design: "SEEDED (synthetic,
  said so in the evidence)") — so `Card`'s "No frozen image yet" placeholder sits in the DOM
  BEFORE the symbol, and the walk's `innerText.split()[0]` read "No" for every such card. Fixed
  in `tools/notebook_w13i2_walk.py`: read the symbol off the card's own image/placeholder
  accessible name instead (`alt`/`aria-label`, which both carry `"{symbol} {tf} chart as of
  {day}"` regardless of whether an image exists).
* **W5 was a real product gap.** `TradeBeforeAfter`'s two `ChartPane` "mini" embeds sit side by
  side (stacking to one column under 640px — that CSS was already correct) and each renders the
  shared chart chrome: the Arithmetic/Logarithmic/Percentage price-scale toggle (`.scaleToggle`,
  a fixed 9px-font button) and the legend's "+N more indicators" overflow chip. Neither clears
  `--tap-min` (44px), and the one existing escape hatch
  (`html[data-mobile-chart-shell]`-scoped CSS in `StockChart.module.css`) is set by exactly one
  caller, `MobileChartsApp.jsx` — the dedicated full-screen phone chart shell, not this card.
  Every other `density="mini"` embed in the app (OptionsFlow's 320px column, the chart builder's
  preview pane, Notebook's own `ChartEmbed.jsx`) inherits the same latent gap; fixing it
  app-wide is out of this lane's scope and blast radius. Fixed narrowly: added `hideScaleToggle`
  to `StockChart.jsx` (same shape as the existing `hideLegend`/`hideCompare`/`hidePriceLine`
  host-veto props, default `false` — every other call site is byte-identical), and set it plus
  `hideLegend: true` on `TradeBeforeAfter`'s two `FrozenChart` embeds. A quick before/after glance
  doesn't need a live crosshair readout or a scale picker.

Both fixes are commit `e796315fe4`. Rebuilt `app/dist` and re-ran the walk with a fresh data
dir at that tip: **7 of 7 PASS**, integrity CLEAN at every checkpoint (raw committed first,
`d108627d1f`, before this doc was written).
