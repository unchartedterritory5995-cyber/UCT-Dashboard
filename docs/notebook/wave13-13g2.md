## 1. What the chip shows, and where it comes from

A row for a symbol the member has written about shows a small chip: the note's own
`builtin:thesis_status` (Watching/Active/Invalidated/Closed) and the distance from the row's own
current price to the note's **stop** -- 13D's `j2_note_levels` projection of `plan_extract`'s
output, read verbatim, never a second parse of the note's body. Hovering (desktop), tapping
(touch, the chip is a real `<button>`), or tabbing to it (keyboard -- focus alone opens it,
mirroring hover) opens a preview: the note's title, its thesis status, its entry/stop/target
levels (each exactly the index's stored price, formatted), and a link into the note. Escape
closes it and returns focus to the chip.

* **One batch request for every visible row.** `POST /api/j2/thesis-chips {symbols:[...]}` ->
  `{SYMBOL: chip}`. The service issues exactly ONE SQL query for the whole requested set
  (`thesis_chips.batch_chips`); the client hook dedupes and uppercases the whole symbol list into
  one SWR key, so N rows cost one request however many rows are on screen. A symbol with no live
  note of the member's is simply absent from the response -- the caller renders no chip, never an
  empty one.
* **Which note, when a member has written about a symbol more than once:** the most
  recently-updated LIVE note that names the symbol -- the same "newest row wins" rule
  `j2_note_levels` itself keeps for a level's side (CLAUDE.md). A note with no stop/target/entry
  row still answers with its thesis status alone; the chip's stop is then null and the preview
  says "No stop in this note," never a fabricated zero.
* **The LEVEL is never recomputed; the DISTANCE arithmetic is.** `thesis_chips.py` reads
  `j2_note_levels.price` straight off the row -- no import of `plan_extract` or any body parser
  (asserted structurally, `test_thesis_chips_module_imports_no_plan_level_parser`). The percent
  shown (`+4.8% above stop`) is plain arithmetic from THAT price to the row's own current price,
  which every row already holds for its other columns -- shipping a second price fetch for this
  one chip would be the thing this module exists to avoid.
* **No new table.** This module reads `j2_note_levels` (13D) and `j2_notes.properties_json`
  (the one property store) and writes nothing of its own, so there is nothing for
  `account_purge` to take -- confirmed by a table-set-diff test
  (`test_the_service_creates_no_table_of_its_own`), not a name guess (other waves' tables already
  contain the substrings "thesis"/"chip").

## 3. The real product bug the walk found, and the fix

The first hover/tap design opened the preview on `mouseenter`/`focus` and **toggled** it on
click. The real-browser walk (`tools/notebook_w13g2_walk.py`, row W5, 390px touch) caught what
jsdom structurally cannot: a tap is not one event. The W3C touch-compatibility sequence is
`touchstart`, `touchend`, then synthetic `mouseover` (the browser also derives a `mouseenter`
from it) and `mousedown` (which moves FOCUS to the tapped button) **before** `mouseup` and
`click`. So on every real touch device the chip opened via the compat sequence and the click that
followed immediately closed it again -- invisible to `fireEvent.click` in jsdom, which fires none
of that sequence.

Fix (`367b6f354`): click only **opens**, it never toggles closed (closing is Escape, or clicking
elsewhere via the existing outside-click handler). Pointer-enter/leave moved from mouse events to
pointer events, gated on `pointerType !== 'touch'`, as defence in depth. `ThesisChip.test.jsx`
gained a direct regression case replaying the exact compat sequence (touch pointerenter, focus,
click) and asserting the preview stays open.

## 5. Decisions

1. **Newest-updated live note wins per symbol**, mirroring `j2_note_levels`'s own tie-break rule
   for a level's side. No status-priority ordering (e.g. "active" over "closed") -- recency is
   simpler to reason about and to mutation-prove, and is documented so a future lane can change it
   deliberately rather than by accident.
2. **The DISTANCE is client arithmetic from a server-sourced level, never a server-computed
   percent.** The server never fetches a price; the row's own current price (already fetched for
   every other column) is the only input combined with the index's stop. This is the same
   division of labour `positionStopDistancePercent` already uses for the Stop Dist column.
3. **Option rows get no chip.** Their displayed "current" is the contract's own mark, not the
   underlying's price; a distance computed against it would be silently wrong. A note on the
   underlying is reached through its own equity row when one exists.
4. **No new table.** Reads two existing tables; writes nothing; nothing for `account_purge`.
5. **Click only opens, never toggles** (section 3) -- found by the walk, not by review.
6. **The P2 mount stays a single, separable commit** (section 4), per ruling P2.
