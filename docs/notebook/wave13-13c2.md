## 2. What this phase did

**Moved the body-building half of `earningsPrep.js` into a new shared module,
`lib/earningsPrepShared.js`**, with zero dependency on note-creation
(`noteCreation.js` -> `createNoteViaApi`), because `noteCreation.js` itself imports
`templateContext.js`, which now imports `requestPrepDraft` FROM the shared module --
a dependency back onto `earningsPrep.js` or `noteCreation.js` would be a cycle.
`earningsPrep.js` is now a ~35-line wrapper: `export * from './earningsPrepShared'` (so every
existing caller -- `ReportingSoon.jsx`, `TickerResearchWorkspace.jsx`, `earningsPrep.test.js` --
keeps importing from the same path, unchanged) plus the one-click door,
`createEarningsPrepNote`, which now just calls the shared `requestPrepDraft` / `buildPrepDoc` /
`prepTitle`.

**The catalog's `earnings-prep` entry** (`notebookTemplates.js`) now declares
`needs: { earningsPrepDraft: true }` and reads `ctx.earningsPrepDraft`:
`build: (ctx = {}) => buildPrepDoc(ctx.earningsPrepDraft || {})` -- the EXACT function the
one-click door calls, on either a real fetched draft or `{}` (already proven by 13C-1's own
`earningsPrep.test.js` to build a whole, valid, honest all-missing doc in the real editor
schema). `defaultTitle` mirrors the one-click door's title once a draft is present
(`prepTitle(ctx.earningsPrepDraft)`, e.g. `"Earnings Prep — NVDA (Mon, Oct 5)"`), and falls back
to the pre-existing ticker-only static title otherwise (`"Earnings Prep — NVDA"`, unchanged --
`notebookTemplates.test.js`'s pre-existing assertion for this still passes verbatim).

**`templateContext.js`'s `assembleTemplateContext`** fetches the draft (the SAME POST the
one-click door makes, `requestPrepDraft`) only when ALL of: the template declares
`needs.earningsPrepDraft`, a ticker is present, and the capability is latched ON client-side
(`earningsPrepEnabled()` -- added after walk run 1, see §3). A refusal (the daily cap, the
gate's own 404) resolves to `null`, never throws, exactly like every other best-effort source in
that file. `STRUCTURE_PROBE_CONTEXT` and `emptyTemplateContext()` both gained
`earningsPrepDraft: null` so the picker's "what does a template read bare vs full" rail
(`TemplatePicker.gallery.test.jsx`'s M-2 check) still covers the new field.

**The template picker path for a manual pick is therefore identical in kind to the one-click
door**: pick with a ticker already known (the deep link `?new=earnings-prep&ticker=NVDA`, or any
future caller of `createNoteFromTemplateViaApi('earnings-prep', {ticker})`) and the note opens
with the real, sourced values -- the SAME cells, the SAME "Source, as of" lines, the SAME frozen
text, and it rightly spends the SAME daily draft. Pick it bare (no ticker, e.g. from the generic
New Note -> Templates gallery) and every cell reads a generic, honest "— not available: Not
available." -- never the old static placeholder table, never an invented number, and it spends
NOTHING from the cap.

## 3. Where the walk found a real gap, and the fix

`tools/notebook_w13c2_walk.py` run 1 (`docs/notebook/evidence/wave13-13c2/walk-run1/`, kept as
the raw record) FAILED one row: faking the client's belief about the gate (`/api/auth/me`
answering `notebook_earnings_prep_enabled: false`) still produced a note with REAL NVDA values
and the day-suffixed title. The draft fetch in `assembleTemplateContext` had no client-side flag
check of its own -- only `needs.earningsPrepDraft` + a ticker -- so a member could pick the
template while the capability is dark-launched off and still reach the live
`POST /api/j2/earnings-prep/{symbol}/draft`. The SERVER route was always the real authority (it
404s while its own env flag is off, and the 404 is swallowed into the honest blank scaffold), so
nothing leaked -- but it broke the "fetches nothing while off" promise every other door in this
lane keeps (`ReportingSoon.jsx`'s own words, in its own header comment).

**Fix:** `earningsPrepDraftFor` in `templateContext.js` now also checks `earningsPrepEnabled()`
before calling `requestPrepDraft`. `templateContext.test.js` gained two tests pinning the gap
directly (unlatched, and explicitly latched OFF -> zero requests to the draft endpoint), and the
three pre-existing fetch-path tests now latch the flag ON first (they had been green before only
because nothing gated the fetch at all). Walk run 2 (below) re-ran clean: zero requests reach the
draft endpoint while the gate is off, and the note still opens with the honest scaffold.
