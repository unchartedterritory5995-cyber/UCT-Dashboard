## What the signed-in run needs, exactly

The tool reads `SMOKE_EMAIL` / `SMOKE_PASSWORD` from the environment
(`tools/hub_nav_smoke.py:237`) and signs in with a single `POST /api/auth/login`, the same door
`tools/mobile_audit.py` uses. Neither variable is set on this machine, and **no synthetic account
exists to put in them**: `ADMIN_EMAILS` on `web` holds three addresses, all personal.

Two things are required, and the second is the one that is easy to miss:

1. **A synthetic account** — never a member's, never the owner's.
2. **A comped paid grant on it.** The tool said so itself: `/dashboard` is **paid-only**, so a
   plain public-signup account cannot reach the one route the 2026-09-10 freeze was reported on.
   A login alone would move this run from exit 2 to a *differently* incomplete exit 2.
3. **Admin, if the hub itself is to be exercised** — at `ROLLOUT_STAGE = 1` an unset preference
   resolves to `isAdmin`, so a non-admin account measures navigation with no hub mounted. That
   still answers box 3 (which is about navigation app-wide, not about the hub), but it cannot
   answer anything about the hub's own surfaces.

Provisioning any of that is a **write to production** and an owner decision, so this run stops
here rather than creating an account.
