## ⚰️ THE FIRST RUN OF THIS PASS REPORTED A PRODUCT DEFECT THAT DID NOT EXIST

It said: *"/charts in landscape-immersive: the hub is still mounted, and `hubViewport.js` says it
must be hidden"*, and it was **wrong**. `HubRoot.jsx:433` renders
`<div data-testid="hub-root" hidden={hidden}>` — the container **stays in the DOM** and takes the
HTML `hidden` attribute. A `querySelector` presence check therefore answers *"did React render the
container"*, never *"can the member see the hub"*.

Measured on the live page before writing a word of it down: `hidden` attribute **True**, computed
`display: none`, bounding box **0x0**. The product was right; the instrument was wrong
(`lesson_did_it_render_needs_the_products_own_answer` — a count can only say yes).

⚠️ **And `offsetParent === null` is not the signal either.** The hub is `position: fixed`, so its
`offsetParent` is null even when it is plainly on screen — measured at 84x84 on `/dashboard` with
`offsetParent` null. The check is now the `hidden` attribute + computed `display` + a non-zero box,
and `--self-check` carries four fixtures for it: a hidden-attribute element and a `display:none`
element must read NOT showing, a real 84x84 box must read SHOWING (the control that stops a
checker which answers "not showing" to everything), and an absent element must read neither.

⚰️ **A second instrument artifact, corrected in the same pass:** the eligibility floor was read
wherever `login()` left the page, which reported `innerWidth 980` — Chromium's fallback layout
width for a document with no viewport meta — inside a 393-wide context. The floor still passed for
the right reason, but an instrument that prints a misleading number invites exactly the false
finding above. It now takes the reading on `/dashboard`.

## What this run still does NOT say

It is Chromium emulating a phone **viewport class**, never an iPhone: iOS Safari is WebKit and
ships `backdrop-filter` only under `-webkit-`, which is the exact prefix that once excluded 100% of
iOS from the hub. This pass can say **where the hub mounts**. It cannot say a gesture works, and it
is not glass evidence for G0-1 or `glass-acceptance.md`.
