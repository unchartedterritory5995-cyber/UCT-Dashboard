## ⚰️ TWO READINGS WERE RETRACTED, AND ONE OF THEM I HAD ALREADY WRITTEN DOWN AS A PASS

⛔ **A drag from the pad without the hold aims at a FAN BUBBLE, and resolves by DIRECTION.**

1. On `/dashboard` a drag straight up from the pad navigated to **Screener**, and it was recorded —
   briefly — as `GS-home-b4` "scrub commit navigates". It was nothing of the kind: straight up from
   the pad is the direction of the **Scan** bubble, so the gesture fired `home.scan`, a `navigate`
   action whose destination is Screener. The outcome was *consistent with* a working scrub-commit,
   which is exactly what made it convincing.
2. On `/morning-wire` the same gesture fired **`wire.voice`** and raised a native iOS
   *"uctintelligence.com Would Like to Access the Microphone"* prompt. It was **cancelled** — no
   capability was granted on a shared device. That prompt is also a modal that blocks further
   browser events, so it had to be dismissed before anything else could be measured.

⭐ **The second one is what proved the first one wrong.** One unexplained navigation reads as a
feature working; the same gesture producing a microphone prompt on another route reads as the
gesture doing something else entirely. Only then did reading `useJoystick.js` settle it.

⚠️ **This is the failure this programme keeps paying for** — an instrument reporting a property of
itself. The check that catches it is not care, it is asking *what else would produce this exact
observation*, and the answer here was "a fan bubble in that direction".
