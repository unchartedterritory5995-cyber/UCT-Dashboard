## A2/A3 · The contract, and what VOID means

`docs/discord-render/instruments/evidence_contract.py` is the single place that decides what an
artifact IS and what it may be used FOR. Four dispositions, not two:

| disposition | meaning |
|---|---|
| **ADMIT** | counts toward the row's verdict |
| **VOID** | marked void in its own file — skipped, **counted and named** |
| **OUT_OF_SCOPE** | not this row's business (a chaos artifact offered to S2) |
| **INCONCLUSIVE** | in scope, cannot yield a verdict for this purpose, and the row must say why |

⛔ **VOID IS RETENTION, NOT DELETION.** `load_harness.py --mark-void` writes the label into the file
and reports sha256 before and after:

```
VOIDED docs\discord-render\evidence\step3\load-real-a-concurrent30.json
  sha256 f14d3859d7f31efa -> 173370ac28219fe2
```

The 30/s run is still the only overload characterisation this programme has. Deleting or moving it
would have destroyed evidence to make a gate tidy.

⛔ **A REJECTED INFERENCE, written down so it is not re-derived.** "cache hits + misses == 0 while
charts were delivered ⇒ the house renderer never ran ⇒ this is the fallback" is **unsound**:
`_cached_render` returns `produce()` untouched when `artifact_cache.enabled()` is False, so zero
counters are equally consistent with *the house ran with the cache flag off*. An artifact with no
renderer label is **UNKNOWN**, and unknown is not fallback.

## A4 · Latency and admission are separate purposes

They always were. A run against the mplfinance fallback says **nothing** about how long a member
waits for a chart the production renderer would have drawn, and **everything** about whether the
queue refuses honestly — a refusal happens at admission, upstream of every renderer.

| purpose | renderer matters? | admitted today |
|---|---|---|
| `s2_latency` | **yes** — fallback/unknown ⇒ INCONCLUSIVE, naming the re-run needed | **0** |
| `admission` | no | **1** (`load-closedloop-30.json`) |
| `s1_ack` | no — the ack runs before a renderer is chosen | **1** |
| `chaos_real` | n/a — each scenario's own `mode` decides | **1** (`chaos-real.json`) |

⛔ S5's floor (99.5 %) and its meaning are **untouched** — that ruling is still with the owner
(Part B5). What changed is which artifacts are allowed to speak to it.

## ⛔ Three defects found in my own work while doing this

1. **A shell heredoc collapsed `\b` to a literal BACKSPACE inside the smoke-title regex**, which
   then matched nothing — a row that would have read NOT MEASURABLE beside a completed smoke. Caught
   only because the fix was followed by a control asserting the pattern matches the real index *and*
   does not match an unrelated one. **Fourth occurrence of this trap in this programme.** Anything
   carrying a backslash is written with the editing tools now, never a heredoc.
2. **Substring anchor counting cannot see indentation.** `"    if art.void:"` occurs inside
   `"        if art.void:"`, so the mutation dry-check reported three matches for a line that
   appears once. Loud in that direction; in the other it silently mutates the wrong branch. Anchors
   are matched as **whole lines** now.
3. **`describe()` carried a second `if art.void:`** — display, not a guard, but textually identical
   to the load-bearing one. Two identical lines where only one matters is how a mutation proves the
   wrong copy. It is an expression now.

## ⚠️ Found, not fixed

**A mark is not a row.** The 3.5 index records `| 1–7, 10–15 | ⛔ NOT RUN |` in one cell — thirteen
rows, one regex match — so the row printed "1 NOT RUN" beside thirteen unrun rows. The verdict was
NOT MET either way (there is a real FAIL on `/buzz`), and MET still requires fifteen individual PASS
marks, so a range mark can only ever under-claim. The row now reports `unaccounted` — the rows no
mark speaks for — alongside the marks. **3.5 stands at 2/15 PASS, 1 FAIL, 1 PARTIAL, 12 rows no mark
speaks for.**
