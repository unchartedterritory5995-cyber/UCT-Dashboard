Branch `feat/pine-w9-t3-capture-tooling`. Design: `docs/pine/W9-STRATEGY-DESIGN.md` r3 (GO-WITH-NOTES, section 5).
Procedure: `docs/pine/capture-queue-2026-09-28.md` plus the strategy additions below. Every probe is
GENERATED by `tools/vendor_harness/w9_probes.py` (one table, the standard plotted set of 5.1 written once;
`--check` fails on a hand edit).

Rules for every row below:
- The owner runs every capture. Values come from the chart model through `tools/vendor_harness/tv_capture.js` v3
  (`__uctVH.capture({..., gradeMethod, gradeRange?, reportPath?})`): never pixels, never the CSV, never `exportData()`.
- A strategy capture is written as tool v3 and carries `provenance.strategySettings` (every Properties input, plus the
  dividend and back-adjustment reads), `provenance.gradeMethod` and, for method (b), `provenance.gradeRange`.
  `verify_capture.mjs` refuses a v3 strategy capture without them, and prints `SETTINGS: AGREE | INCONCLUSIVE`.
- The settings are set in the source only. A Properties value that disagrees with the declared one is INCONCLUSIVE.
- Method (a) is `NYSE:RDDT 1D` from the 2024-03-21 listing (`startsAtBar0` asserted). Method (b) wraps every order call
  in `time >= X and time < Y` (`tools/vendor_harness/range_guard.py`) and records `gradeRange`.
- No probe was compiled or run when it was written. A compile refusal by TradingView is a recorded datum, not a retry.
- The report reader waits on W9-C0 (the first row). Until its path is pinned in `tools/vendor_harness/strategy_report_slots.json`
  every report slot refuses by name.

## E. Grading the 70 (not a probe table)

The 70 strategies are graded from their own sources, unmodified on RDDT first (method (a)); routing to a
`range_guard.py` variant on SPY uses TradingView's closed-trade count only (design 5.2 E, T2 step 0).

A SPY grading variant is made at capture time, because its window X is TradingView's first bar plus 5 times the
script's longest lookback, and TradingView's first bar is only known from Q-S1n's capture. The two commands:

    python tools/vendor_harness/range_guard.py window <Q-S1n SPY capture.json> --lookback <L>
    python tools/vendor_harness/range_guard.py rewrite <source.pine> <w9-g-slug-spy.pine> --from-ms <x> --to-ms <y>

`window` prints `fromTime`, `toTime`, `warmupBars` for `gradeRange` and `x`, `y` for the guard. A source with no order
call, an order call that does not start its line, or a source already guarded for another window is refused by name.
The committed corpus variants of the design are therefore produced locally from the same two commands (deviation
recorded in `docs/pine/evidence/2026-11-05-w9-t3/EVIDENCE.md`).
