## 1. Trace of one user message

Example: member types **"add vwap and rsi, then make it a 5 min chart"** on a two-chart board with no chart clicked. The path is the legacy (NL-1 off) path, which is what production runs (`nl1Enabled()` is false unless `localStorage uct.agent.nl1='1'` AND server `UCT_AGENT_NL1=1` — `app/src/agent/nl1/interpreter.js:29-32`, `api/services/uct_agent/turn.py:163-165`).

### 1.2 fastPath — `app/src/agent/fastPath.js`
- `fastParse(text, {host})` → `fastParseExact` (`fastPath.js:200-216, 225-235`): message cleaned, length ≤ 160 chars (`:227`), control words first (`controlWord`, `:238-264`), then `capabilityPhrases` (`:272-290`).
- **How phrases are contributed by capabilities**: there is no phrase table in fastPath. `matchClause` iterates `allCapabilityNames()` and calls each capability's optional `fast({raw, lower, core, host})` (`fastPath.js:83-97`). Examples: `chart.setTimeframe` `fast: ({core}) => firstMatch(TF_WORDS, core)` (`capabilities/chart.js:382`), `chart.setType` (`chart.js:367`), indicator adds/updates (`capabilities/indicatorEdits.js:713,755,804`), watchlist list query (`capabilities/watchlist.js:389`). 20 capability files declare `fast`, ~55 declarations in total (grep). `fastWhole` capabilities (whole-sentence lists like "add RKLB, PLTR to Momentum") are tried before clause splitting (`fastPath.js:103-117`).
- Normalisation (`canon`, `fastPath.js:34-75`): number words, "5m"→"5 minute", "exponential moving average"→"ema", politeness/filler stripping, verb synonyms ("throw/slap/plop"→"add", "get rid of"→"remove"). `LEAD`/`TAIL` strip "switch/change … to" scaffolding (`:26-27`).
- Target hints are lifted off the text before clause parsing (`extractTarget`, `fastPath.js:138-170`): "both/all N", plural pronouns, ordinals ("the second chart"), positions ("top-left"), a chart named by symbol/timeframe (`deixis.chartQualifier`). The fast path never resolves a target itself; the panel does (`useAgent.js:1435-1499`).
- Clauses are split on `, ; and then &` (≤ 6) and **every clause must match exactly one capability** or the whole message goes to the model (`fastPath.js:12-13, 277-289`); a bare follow-on clause inherits the previous verb (`:283`). Ambiguous phrase (two capabilities claim it) → model (`:97`).
- Typo lane (`fastPath.js:182-217`): `correctTypos` against a lexicon generated from the registry/catalog/member names (`nl/lexicon.js`); used only when exactly one distinct action results **and** it is `risk: local`, reversible, not a ticker-bearing action (`SYMBOL_ACTIONS`, `:189-199`).
- For the example message: "add vwap" and "rsi" match `indicator.add` (indicatorEdits), "make it a 5 min chart" → `chart.setTimeframe`. Ops of two kinds → `useAgent.js:1419-1434` needs exactly one target per kind; with two charts and no click → not all targets resolved → falls to `kindsOf.length===1` check (false) → … → `planCompound` → model path. (A one-chart board would execute instantly with path `'fast'`.)

## 3. "Understands but refuses / fails to execute"

**How turn.py constrains the model's action list.** The server has **no action list of its own** (`turn.py:7-10`). The browser sends the manifest (routed subset, ≤ 60 entries, `validate_manifest` `turn.py:168-213`); the schema's `action` enum / `const` is built from exactly those names (`:248, 390`); `sanitize_envelope` refuses any op whose action is outside `cap_names` (`:1256`). Legacy `MAX_CAPABILITIES` and NL-1 `MAX_CAPABILITIES_NL1` are both 60 (`:88-94`). A manifest over 60 is refused whole, never trimmed (`:176-183`).

**Is there a server allowlist narrower than the manifest?** No. The only server-side narrowing is: (a) `LOCAL_ONLY_ACTIONS` = `breadth.show`, `breadth.history` whose results never return to a model (`:679`); (b) `EXPLICIT_OK_ACTIONS` = `indicator.saveDraft` (`:58`); (c) `enforce_approval` escalates confirm/irreversible actions to propose (`:1321-1332`). The narrowing that matters happens **before** the server, in `routeManifest`: a message routed to the wrong groups never offers the right action; the model can only ask for groups by id (`need_groups`) and gets one more call (`budget.py:55` 2 calls/request; `useAgent.js:1651-1673`).

**What happens when the model emits an action not in the manifest.** `TurnError("UCT Agent planned an action that doesn't exist…")` → HTTP 400 → the browser shows the sentence; nothing is retried (legacy). Under NL-1 the same case is first sent back once as `<validation_error>` (`nl1_plan_problems` `:1397-1427`, `:1725-1734`).

**What `unsupported` is used for.** A model disposition for "asked to DO something no available action can do" with a one-word `unsupported_category` (`turn.py:464`); ops forced empty; the browser shows the reply and records nothing executable (`useAgent.js:1705-1711`). The browser also records `kind: 'unsupported'` locally for Multi Chart grid mode (`:1243`). Telemetry stores `unsupported_category` (`routers/uct_agent.py:414`). The server's `unsupported_category` is never validated against anything.

**Multi-op turns.** The prompt instructs ONE plan for a whole request, steps connected by `as` aliases (`turn.py:469-470`). The browser's planner then: splits deferred (`watchlist.open`) and `sequential` (indicator edits) ops into follow-up executions (`useAgent.js:500-538, 846, 961-975`); fan-out of the same op on several charts (`:197-205, 677-715`); composition refs (screen → list) proposed first, resolved at apply (`compose.js`, `useAgent.js:579-634`); refuses create+edit mixes and `exclusive` ops with anything else (`executor.js:118-130`). `compound.js` is a **deterministic, model-free** reader for multi-clause messages (`planCompound`, `compound.js:90-120`): every clause must be readable by an existing layer (grid / fast / follow / pane) or the whole message goes to the model; ≤ 6 steps (`:38`), each ≤ 12 ops (`:39`); `runCompound` (`useAgent.js:1177-1224`) executes step by step and **stops** at the first step that is refused, asks, or needs approval ("Done N of M steps, then stopped at …").

**Per-turn caps.**
- Model: `MAX_OPS` 12 per plan (`turn.py:61`, mirrored `manifest.contract.json:22`, `useAgent.js:78`); client planner 24 units / 96 raw ops (`executor.js:26`); `MAX_MESSAGE` 2 000 chars (`turn.py:59`); 2 paid model calls per request (`budget.py:55,101`); 1 research call (`turn.py:62`); `MAX_TOKENS` 2 048 (`:63`).
- Rate: 20/min, 300/h per member, 120/min global, 1 in flight, 150 s lease (`limits.py:33-39`); 300 requests/day (`routers/uct_agent.py:94-98`); $5/day Agent, $15 shared (`budget.py:54`).
- Data gateway (dark, `UCT_AGENT_DATA`): `MAX_READS_PER_TURN` 8, `MAX_SCANS_PER_TURN` 1 (`marketdata/gateway.py:52-53`); screener `MAX_FILTERS` 12 (`capabilities/screener.js:48`), `compose.MAX_TOP` 1 000 (`compose.js:28`); `chart.compare` ≤ 10 overlays (`references.js:34`).
- Compound: 6 steps, 12 ops/step (`compound.js:38-39`); follow-ups ≤ 24 ops (`docs/agent/PHASE2-NL-INTELLIGENCE.md`).

**Net effect on "understands but can't execute".** Four mechanisms produce it: (1) routing omitted the group (one reroute, then "too many parts"); (2) the chosen capability's `check()` refuses for a product reason (read-only chart, floating widget, protected layout, missing room); (3) the planner's structural rules (exclusive `layout.open`, create+edit mix — documented gap G10 in `NL1-HANDOFF.md`); (4) the member is a non-admin or the capability is flag-gated (`available()`), in which case the model never sees it and answers `unsupported` in its own words.

## 4. Multi-step planning and conversation state

- **No multi-turn planner.** Each turn is one plan (`turn.py:469-470` "WHOLE REQUESTS … ONE plan"). Dependent steps inside one plan are expressed by transaction-local aliases (`as`, `executor.js:15-19, 39-57`) and typed refs `{from, top}` (`compose.js`), resolved at apply time with fresh producer runs (`useAgent.js:612-632`). The canonical "scan → watchlist add → open" works this way: `screener.run as screen1` → `watchlist.create as list1` → `watchlist.add {symbols:{from:'screen1', top:null}}` → `watchlist.open` (deferred step after the rest lands, `useAgent.js:207-239`). "Open the watchlist you just created" in a later turn relies on the model finding the name in context (`turn.py:493`).
- The deterministic `compound.js`/`runCompound` sequences steps only for board/indicator requests it can read itself (grid → indicator adds → styling), with a working set of charts carried forward (`compound.js:20-23, 176-199, 294-297`).
- **Conversation state that carries result sets.** `memory.js` (browser session only, cleared on new chat / chat switch / reload — `:28, 164`, `useAgent.js:1873,1881`): result sets (≤ 3 × 50 tickers, 30 min TTL — `:31-33, 64-70`), subject chart/indicator, last change with its Undo id, last turn's steps, indicator set, mentions, corrections. `references.js` resolves "the third one"/"the others"/"do the same on the right one" from it, re-validated on the live board (`:57-129`). `deixis.js` resolves "this chart / it" to the **clicked** chart only (`:1-10`).
- **What is persisted.** Server `store.py`: conversation rows (`member | agent | outcome`, text ≤ 4 000 chars, `data` ≤ 20 000 chars incl. envelope / views / outcome kind — `:36, 147-187`), titles, telemetry. The model's memory of prior turns is the last 36 stored rows (`turn.py:906`). The **lastScreen** standing source lives in the browser screener cache (`registerOutputSource`, `capabilities.js:137-145`; `screener.js:607`), not on the server. Proposals and the Undo stack are per session (`useAgent.js:444-445`).

## 6. NL-1 hybrid

- **What it is** (`app/src/agent/nl1/interpreter.js:1-17`, `selection.js:1-21`, `turn.py:89-95, 518-539, 542-554`): the model reads every message except exact `undo / do it / cancel` (`exactLane`, `interpreter.js:38-52`); no fast path, no regex routing, no keyword-gated context. The request carries a **fixed core** (charts, indicators, screener, agent — ≤ 45 actions, sent first so the server can cache it), pinned groups (waiting proposal, last change, pending question), ≤ 3 model-requested groups (one reroute), and word-router additions packed into the 55 budget (`selection.js:26-33, 73-94`); whole groups only, unselected groups named. Every action is in the compact `args_json` shape; NL-1 rules + glossary join the cached system prompt; choices carry context refs; `correction: {replaces: "last_change"}` lets the browser reverse the Agent's previous change through the existing Undo before applying the new one (`interpreter.js:207-215`, `useAgent.js:1826-1837`); one **repair** round trip with planner refusals (`interpreter.js:168-178`, `useAgent.js:1683-1695`); server repair on schema/target problems (`turn.py:1397-1427, 1725-1734`); "no wording-based approval shortcut" (`withoutWordingApprovals`, `interpreter.js:190-195`); plans made without groups the member's words pointed at are only proposed (`useAgent.js:1699-1703`).
- **Is it on?** No. Browser flag `localStorage uct.agent.nl1` and server `UCT_AGENT_NL1` both default off (`interpreter.js:11-13, 29-32`; `turn.py:163-165`; `routers/uct_agent.py:195`); `GET /api/agent/config` reports `nl1`. Memory note: PR #439 promoted 2026-10-20 dark, re-verified 2026-10-25, flags OFF; activation needs a paid eval + owner decision (`NL1-SELECTION.md` release note).
- **What it adds over fastPath**: model reading of casual/typo/slang wording beyond the lexicon's safe corrections; references resolved by the model from `conversation_memory` + `last_change_detail` (with targets and args, `interpreter.js:139-159`); typed answers to pending questions read with the question (`pending_question`, `:100-105`); corrections; protected layouts marked in context (`:91-97`); reference data (indicator catalog, screener fields) in a cached block (`splitReference`, `:125-137`, `turn.py:1432-1448`). It removes nothing: the legacy layers are bypassed, not deleted (`NL1-PROGRESS.md` gap 4), and every safety check downstream is unchanged. Cost: every request is a model call (~24k tokens FULL, ~95 % cacheable) versus the legacy path where 0.62–0.84 of corpus cases reach the model.
