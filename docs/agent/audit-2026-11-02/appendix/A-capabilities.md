## 5. Server side: action list, allowlist, `require_admin_dark`

- **Action list construction** (api/services/uct_agent/turn.py): `run_turn` (:1562) → `validate_manifest(capabilities)` (:168-213) keeps every entry whose name matches `^[a-z][a-zA-Z0-9]*(\.[a-z][a-zA-Z0-9]*)+$` (:97), whose `args` is a closed, all-required object schema (`_closed_schema` :145-160), ≤ 6000 bytes (:193); summary cut to 400, hints to 1000, risk coerced to local/confirm, reversible/undo normalised (:200-212). Over `MAX_CAPABILITIES = 60` per request (:88) the turn is **refused whole**, never trimmed (:177-183). The prompt's action list is generated one line per capability by `_catalog_lines` (:630-651) inside `system_prompt` (:515-520); the structured-output schema is `envelope_schema` (:385) with per-action variants up to ~11 actions, then the compact `{action enum, args_json}` shape (`compact_ops` :225, `_compact_op_schema` :244-248 — the enum IS the manifest's names).
- **Allowlist**: there is **no server-side allowlist of capability names**. `cap_names = {c["name"] for c in caps}` (:1663) is derived from the manifest the browser sent; `sanitize_envelope` (:1233) raises if any op names an action outside it (:1256) and turns unknown targets into a clarify (:1270-1281); targets must be refs the browser's own context published (`_context_refs` :1499,1600). The only fixed name sets are `EXPLICIT_OK_ACTIONS = {"indicator.saveDraft"}` (:58) and `LOCAL_ONLY_ACTIONS = {"breadth.show", "breadth.history"}` (:679). Safety therefore relies on the browser registry re-validating every op (`shapeError` / `availableCapabilities`, capabilities.js:165-171,230-251; executor.js:83-95) before execution, as README.md states ("the server never mutates a workspace").
- **Approval boundary**: `enforce_approval` (:1321-1333) rewrites an `apply` to `propose` whenever an op's capability is `risk: confirm` or `reversible: false` (except `indicator.saveDraft`); mirrored in the browser by policy.js:34-37 and the contract's `approval.explicitOk` (manifest.contract.json).
- **`require_admin_dark`** (router:89-91): a FastAPI dependency = `require_paid` (402 unless `is_paid_user`, :83-86) then `auth_middleware.require_admin(user)` (403). Docstring: "DARK ROLLOUT: admins only. Delete this dependency to open to paid members." Every Agent route uses it, including `/api/agent/config`, so a non-admin browser never even learns the flags.
- Contract tests: tests/test_uct_agent_contract.py validates the same golden file with the server validator/schema/prompt (:57-87) and holds the limits equal to manifest.contract.json (:39); agentContracts.test.js:35 regenerates the golden only under `UPDATE_AGENT_GOLDEN=1`.

## 7. Findings (most important first)

1. **Everything is admin-dark twice.** Server: every `/api/agent/*` route depends on `require_admin_dark` (router:89-91 and each decorator). Browser: `agentFlag.js:25 DEFAULT_ON = false` plus admin role. So Class A means "works for an opted-in admin"; no capability is member-visible today regardless of any other flag. Lifting dark = deleting one dependency (router:27-28), which would expose all 121 golden capabilities at once to paid members — there is no per-capability member gate other than `createIndicator` (6 caps) and `manageIndicators` (11 caps).
2. **The server trusts the browser's manifest; there is no server allowlist of action names** (turn.py:168-213, :1663). Capability names, risk and reversibility come from the client. A tampered client could label `watchlist.delete` as `risk: local, reversible: true` and `enforce_approval` (:1321) would pass it — but nothing on the server executes ops, and the real registry re-applies its own risk (policy.js:34-37) and shape (`shapeError`), so the exposure is limited to the model's prompt/plan, not to data. A design decision to state in the audit, not a defect.
3. **Only 2 of 13 gateway kinds have a browser capability** (stock.quote, stock.dailyBars; plus screen.run/screen.saved used inside screener.run/runSaved/listSaved). `fundamentals`, `earnings`, `news.company`, `themes`, `breadth.current`, `ratings`, `screen.count` are server-registered but unreachable from the Agent UI (§6). The existing stock.* / news.* queries still use the legacy product routes (stock.js:5-9, news.js:5-8), so turning the gateway on changes nothing for them.
4. **`manageIndicators` is applied inconsistently**: computed in useAgent.js:1549 and passed only to `manifestFor` (:1612) and NL-1 (:1568); the `capCtx` used for `planOps`/`shapeError`/`answer` (:306, :531, :593, :647, :684, :729) is `{surface, createIndicator}` only, so `available()` for indicatorEdits (`ctx.manageIndicators !== false`, indicatorEdits.js:418) is true at plan time even when the manifest hid those actions. Harmless today because `planCheck` refuses READONLY charts (:844), but manifest and planner disagree about availability.
5. **Weak test coverage on several registered actions.** 0 JS test files name `chart.renameTab` (board.js:1217) or `drawing.list` (drawings.js:177); 35 capabilities appear in exactly one JS test file (e.g. chart.setCandleColors, chart.addCustomTimeframe, watchlist.setNote, widget.move, widget.showScan, chart.applyThemeAll, widget.selectTab/renameTab/closeTab, chart.addTab/selectTab/closeTab/linkTab, drawing.setVisible/lock/setLevel/setAllVisible, chartSetup.removeTimeframe/favoriteTimeframe/compareDisplay/saveTemplate, pane.resize, indicatorCopy.copyTo, definition.describe/duplicate, stock.earnings, settings.show/setAppTheme/setAlertSound, screener.state, alert.list, news.catalysts). Server-side, 59 of 123 names never appear in tests/test_uct_agent*.py (expected: the server is generic).
6. **Stale server comment**: turn.py:92 says "The whole catalog (~91 actions) is over it" — the catalog is 121 (123 with data). NL-1 unrouted is therefore still refused whole (:89-94); routed NL-1 (nl1/selection.js) must keep each request ≤ 60.
7. **No stubbed execution path found.** Every write kind's `commit` calls a product writer and `landed` reads back (§3). The deliberate no-op commits (`screener`, `market`, `breadth`, `about`, `guide`) belong to query-only kinds. Partial by design: `indicator.undoDraft` (needs `undoStepId`, indicatorAuthoring.js:1034 — the one Class C), `chart.goToDate` Undo only with a readable view (chart.js:260), `breadth.show` universe `uct` answers a fixed sentence (breadth.js:104), `app.open` has no target when the host lacks `navigate` (app.js:45), `widget.setLink`/`chart.linkTab` refuse E–H without the product flag (board.js:56-57).
8. **Irreversible-but-local**: `layout.saveCurrent` is `risk: local, reversible: false` (layout.js:495) — still always proposed via `reversible:false` (policy.js:37, turn.py:1328), so behaviour is correct, but it is the one entry where risk and reversibility disagree.
9. Catalog bounds: manifest.contract.json `catalog.maxRegistered: 200`, `maxGroupSize: 40`, per-request 60, routing threshold 55; largest kind is board (21); enforced by agentContracts.test.js:71-78 and test_uct_agent_contract.py:50.
