## What I checked
### Non-admin and anonymous users (highest risk)
- `AgentProvider` (App.jsx, wraps RouteErrorBoundary inside AuthProvider): `allowed = useAgentFlag() && role==='admin'`. When it is false, the dock, `AgentNavBridge`, idle panel preload and `uct-agent-open` listener are not mounted, and `AgentDockButton` returns null. Nothing new is added to the DOM.
- Network: there are no new requests. `useJournalAgentHost` → `useJ2Notes({enabled: !!app?.allowed})`, which passes a null SWR key when off. `useScreenerAgentHost` calls `useSavedScreens()` unconditionally, but that SWR key (`/api/screener/saved-screens`) is already mounted on the same pages: FocusList line 493, and `ScreensManager` is always rendered in ScannerShell, embedded or not. The call is deduplicated, so no new request goes out.
- Hook order: on every touched page, the new hook comes before any early return. I checked FocusList (hook at 841, after the `body` if/else and no earlier return), ScannerShell (355), Calendar (851) and JournalLayout (top). For Breadth, the hook is now at 968, before the `overview` and `cot` early returns. That is correct. `breadthTabHookOrder.test.jsx` covers it with and without the provider.
- Bundle: AgentPanel stays lazy. Page hosts are in a separate shared chunk `usePageAgentHosts` (6.2 KB) that only loads with the lazy page chunks, and no capability code reaches it or the main chunk.

### Admin with the switch off
- Same code path as a member. The UI is identical to master.

### Admin with the switch on
- Writes go through each page's own writer only. `screener.openSaved` → the page's `applyScreen`/`applySpec` (Screen menu door). `journal.createNote` → `createNoteViaApi` (the Notebook's path) and then the page's refresh. Undo is a DELETE `/api/j2/notes/{id}` of that one created id (Trash, restorable). Breadth and Calendar are read-only.
- Receipt and Undo name the page: "Opened "X" on the Screener page (was "Y")" and "Added note ... to your Notebook". Page writes are offered only on their own surface (`surfaces: ['screener'|'journal']`, `onSurface`). Tests check the manifests (the journal page offers no chart, trade or position capability).
- Approval: a single reversible note-create applies with Undo and no Approve click. That is existing executor/policy behaviour (`createsResource`, same as watchlist and savedScreens). It is not new, but the owner should know a note write can happen from an explicit command or a model-planned one.
- F-16: the screener query caps only widened from `['charts']` to `['*']`, and the refusal logic is unchanged. `qa/f16Rails` and the scan suites pass.
- Cross-user: the handoff slot is per-tab React state, and nothing uses it yet (C3 is not in these PRs). Notes are created and deleted with the member's own session. The server owns the authorization, and the only id that can be deleted is one the Agent just created.
- No backend change. The only file under api/ is the `section_b_requests.json` SAT capture. `require_admin_dark` is already on master. There are no budget, limit, model, auth or isolation changes.
- Cost: Explain and Show are local (fast path or guide registry, no model turn, as asserted by tests). Do asks with the page's own choices and then uses the ordinary planner turn, so it stays under the existing per-turn and daily caps.

## Non-blocking findings (follow-ups)
1. **One extra render of every host page for all users.** `useAgentPageHost` registers for everyone, including members and anonymous users (app/src/agent/agentApp.js:21-25). `registerPage` then sets provider state, so the context value changes and the page re-renders once more on mount and unmount (Breadth, FocusList, ScannerShell, Calendar, JournalLayout consume the context). There is no functional effect and no network. Minimal fix: return early in `useAgentPageHost` when `!app?.allowed`, and skip `useLiveHost` building the same way.
2. `useSavedScreens()` in `useScreenerAgentHost` (hosts/usePageAgentHosts.js:43) adds no request today only because of SWR dedup with sibling mounts, which is fragile. Pass a null key when `!app?.allowed`.
3. `AgentPageDock` renders outside `RouteErrorBoundary` (App.jsx), so a panel crash, possible only for an admin with the switch on, would reach the top-level boundary. Consider wrapping the dock in its own boundary.
4. Main chunk is +9.0 KB raw (see below), from the static `AgentProvider` import (agentFlag, agentWidth, AgentNavBridge, CSS-module class map). This is acceptable. It could be trimmed further by keeping only the gate in main and lazy-loading the dock.
