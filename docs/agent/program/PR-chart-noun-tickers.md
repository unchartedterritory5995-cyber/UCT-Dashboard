## What changes

The Agent's chart-noun vocabulary now covers the chart-GEOMETRY word family: width / wide / widen / narrow / header /
resize, in every inflection. A request that uses one of these words:

1. **Is never read as a ticker.** In `marketDataPhrases.js`, `CHART_GEOMETRY_WORDS` joins `CHART_PART_WORDS`, so it is
   also in `NOT_A_TICKER`. A lower-case sentence that names a chart part or a geometry word is not a price question, so it
   goes on to the model. "narrow the price column to 50" no longer gets "I'm not sure which instrument 'narrow' means".
   A ticker typed in capitals or `$`-prefixed still prices (`WIDE`, `$NARROW`).
2. **Routes to the chart.** In `routing.js`:
   - `CHART_GEOMETRY` (the family, with a board noun such as chart / widget / panel / window / cell / tile) brings the
     workspace group, so `widget.resize` reaches the model for "widen the chart", "the AAPL chart is too narrow" and
     "change the width of this chart". Before this, only "wider", "narrower" and "resize" did.
   - The board noun is required, so "narrow my screen to tech stocks" stays a screener refinement.
   - `headers?` and `ax[ie]s` name the charts group.
3. **Reads "widen / narrow <a chart>" locally** (`board.js` `SIZE_VERB_RE`). These read exactly like "make <that chart>
   wider / narrower" (the same `widget.resize` op), but **only when the named widget is a chart**. "narrow the watchlist"
   may mean a filter, so it is left to the model.

No lookbehind (#1022 rail). The only new assertion is a lookahead in `CHART_GEOMETRY`.
