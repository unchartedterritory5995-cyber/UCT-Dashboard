## BLOCKER

### B1 — Expected-move chain fetch silently truncates dense chains (wrong numbers on the biggest names)
`polygon_options.get_chain` issues ONE page with `limit=250` and never follows Polygon's `next_url` — `api/services/polygon_options.py:145-148`. A single weekly expiry on TSLA/NVDA/SPY-class names easily exceeds 250 contracts (calls+puts); the page is cut by sort order, so whole strike ranges — or effectively all of one side — can be absent. An ATM-straddle computed from a truncated chain returns a plausible-but-wrong expected move, silently, on exactly the highest-attention reporters. Fix before P4: paginate `next_url`, or bound the request with `strike_price.gte/lte` around spot (spot available from `/v2/snapshot` first), or both. NBBO (`last_quote.bid/ask` :107-108), IV (:117), OI, and break-even are all present and sufficient once the fetch is correct.

### B2 — Earnings-history reaction math has no BMO/AMC session source
The FMP `stable/earnings` parse keeps only `date` + eps/revenue fields (`api/services/earnings_estimates.py:341-360`); no session/time field is read, and the Finnhub gap-fill rows key on period-end, not report session. Reaction day differs by session: AMC → next trading day; BMO → same day. Without a session bit, "next-day reaction / gap / drift" is off-by-one-day for roughly the AMC half of history. Spec §6 names only "FMP stable/earnings + internal bars store" — insufficient as specified. Options: Finnhub earnings-calendar range (retains history; carries `hour` for ~90% of rows per the 7/30 backfill work in `api/routers/calendar.py`), a deterministic gap-comparison heuristic (|open-gap on date| vs |on date+1|), or store-forward from the live calendar feed. Whichever is picked must be in the endpoint design + pytest fixtures, with honest labeling for the unknown-session ~10%.

### B3 — Ownership consolidation direction contradicts the spec's own design
Spec §5.3 says "consolidate on `/api/research/ownership`", but the design (§4.3.4 + §5.3) requires **13F flow chips NEW/ADDED/TRIMMED/CLOSED + holder deltas** — and those exist ONLY in the other endpoint:
- `/api/ownership/{sym}` → `institutional_holdings.get_ownership` (`api/services/institutional_holdings.py:159-189`): FMP-first, `_classify_change` computes new/added/reduced/sold_out + biggest buyers/sellers. Auth-gated (`api/routers/analyst.py:32`, `Depends(get_current_user)`).
- `/api/research/ownership/{sym}` → `api/services/research/ownership.py`: yfinance `institutional_holders` (no prior-shares deltas) + short interest + insider. **No auth dependency** (`api/routers/research.py:40-46`).
Payload shapes are disjoint (`{ticker, inst_pct, top_holders, biggest_buyers, biggest_sellers}` vs `{sym, institutional:{pct_held, holders}, short, insider}`). Consolidating on the research endpoint as-is loses the exact fields the new UI needs. Correct plan: merge the FMP delta logic INTO `research/ownership` (it's the superset home — short + insider live there), THEN alias. Also decide the auth posture deliberately — the modal currently reads an authed endpoint; the research one is anonymous. Consumers of `/api/ownership`: `app/src/hooks/useOwnership.js:9` → `OwnershipPanel` → EarningsModal, TickerPopup, FundamentalsWidget (see M7).

## MAJOR

### M1 — URL state: raw pushState fights React Router; CatalystFlow double-mounts
Calendar already owns search params via `useSearchParams` — `?week` at `app/src/pages/Calendar.jsx:89`, `?d` at :98. Raw `window.history.pushState` desyncs router state under react-router-dom@7 (`app/package.json:37`), and any later `setSearchParams` call drops `?earnings` unless every call site merges it. Worse: the Dashboard mounts **two live CatalystFlow instances simultaneously** (`app/src/pages/Dashboard.jsx:108` desktop tree + `:170` mobile tree — both in the DOM, CSS-hidden), so a URL-driven open renders two modals. Cleanest ownership: a `useEarningsModalRoute` hook built on `useSearchParams` (merge-preserving), param honored ONLY on `/calendar` + `/calendar/mystocks`; CatalystFlow keeps plain local state (deep-link semantics on `/dashboard` are dead weight anyway — its modal `row` comes from today's bmo/amc wire list, `app/src/components/tiles/CatalystFlow.jsx:121-137`, so an arbitrary deep-linked sym is unbuildable there). The spec must also define sym→row resolution for deep links on /calendar: the modal requires a `row` built via `toModalRow(entry)` from the loaded feed (`Calendar.jsx:491-493`) — behavior when `?earnings=SYM` isn't in the loaded week is unspecified.

### M2 — "Arrow keys reuse mounted shell" is contradicted by all three current mounts
Every mount wraps the modal in a sym-keyed boundary: `<ErrorBoundary key={selected.row.sym}>` at `Calendar.jsx:633`, `MyStocksHub.jsx:438`, `CatalystFlow.jsx:146` — symbol change = full remount today. Shell reuse requires removing that key (keep the boundary; the modal already resets state on `row?.sym` change, `EarningsModal.jsx:178-182`). And the spec's "AbortController is sufficient" claim is only half-true: the modal's own fetches are aborted (`EarningsModal.jsx:189, 214`) but the child SWR hooks (AnalystPanel, OwnershipPanel, SentimentGauge, tweets, fundamentals) are not abortable — stepping through a 40-name day fires ~6-10 uncancellable server fetches per stop, the exact per-card-storm class the calendar work banned ("never fetch per-card fundamentals — 60-req storm", CLAUDE.md calendar invariants). Add a settle debounce (~200ms) before the Setup section's data hooks fire, and keep the price poll only during stepping.

### M3 — ECharts: compatibility yes; the claimed bundle win does not hold as scoped
`echarts-for-react@3.0.6` + `echarts@6.0.0` (`app/package.json:28-29`) — `echarts-for-react/lib/core` accepts an injected `echarts/core` instance, so new kit charts CAN be tree-shaken. But the "backlogged echarts bundle-shrink" is only executed if the **5 existing full-entry imports** also migrate: `app/src/pages/BreadthCharts.jsx:3`, `app/src/pages/breadth/views/TreemapView.jsx:7`, `app/src/pages/journal-2-0/tabs/AnalyticsTab.jsx:14`, `.../components/analytics/RiskExitsSection.jsx:22`, `.../components/PerformancePanel.jsx:9`. Three of five are Journal 2.0 — outside this initiative's stated surfaces. One surviving `import ReactECharts from 'echarts-for-react'` keeps the full echarts index (which side-effectfully registers everything) inside `vendor-echarts` (`app/vite.config.js:109`, object-form manualChunks — keep object form per `feedback_vite_manualchunks_object_form`). Also: the spec's "12 existing echarts files" is wrong — that grep counts `recharts` (substring match: OptionsFlow.jsx etc.) and test files; real prod import sites = 5. Either scope the 5-file migration into P1/P5 explicitly or drop the bundle-win claim.

### M4 — `get_year_earnings` can't feed the lollipop as implied
Two mismatches with §4.3.2/§6: (1) `_year_earnings_from_fmp` **drops not-yet-reported rows** (`earnings_estimates.py:348-349` — "upcoming quarter, nothing reported yet"), so the "dashed next-quarter estimate" dot has no source through this function; (2) it's year-keyed (4 fiscal quarters per call), so an 8-quarter window means 2-3 calls each re-fetching the same `stable/earnings` payload. The new endpoint should add a "last N quarters, raw" accessor over `_fmp_get("/stable/earnings", ...)` reusing `_earn_row_preferred` dedup (`earnings_estimates.py:367-374`) and keeping the forward-estimate row — not compose `get_year_earnings`.

### M5 — polygon_options: three concrete gaps for the expected-move use (importability is fine)
(a) **No symbol mapping**: `massive.to_polygon_symbol` exists (`api/services/massive.py:39`, BRK-B→BRK.B) but polygon_options never applies it — class-share underliers return empty chains. (b) **Expiry selection**: no-arg `get_chain` narrows to the FRONT expiry (`polygon_options.py:176-183`) — wrong for any report >1 week out (front weekly expires before the report). The straddle service must select via `list_expirations` (first expiry ≥ report date) and pass `expiration=` explicitly — exactly the logic the outgoing yfinance version already implements (`api/services/earnings_enrichment.py:243-268`); port it. (c) **Cache**: bare 60s `TTLCache`, no single-flight (`polygon_options.py:26-28`) — the spec's own "15min + serve-stale" must actually be built; `ServeStale` is on master here (`api/services/serve_stale.py`, consumed by `api/routers/calendar.py:26`, `wire.py:17`, `signature.py:48`). Importability verified good: module deps are httpx + stdlib-only `api/services/cache.py` (:1-4) — no voice, no yfinance, no pandas.

### M6 — Nightly implied store: placement and capture timing are unspecified and easy to get wrong
Where: WEB service. The scheduler exists (`BackgroundScheduler`, America/New_York tz, `api/main.py:2456`; `_ET` at :13 per house cron rule), and the store must be readable on the request path — the worker's `/data` is a **separate volume** the web pod cannot read (only bars cross via the R2 merge bridge). Pattern: web-side APScheduler job + web `/data/*.db` SQLite (cot.db/catalysts.db idiom). When: capture keyed to the PRE-report session — a post-close run (options stop trading ~4:15 pm ET) is safe for that night's AMC names and tomorrow's BMO names; a next-MORNING run would store IV-crushed values for last night's reporters and poison the "implied at the time" history. Add the weekday/holiday guard (`lesson_scheduled_jobs_holiday_guard`) and never store a failed fetch as a value.

### M7 — P2 blast radius is wider than "3 mount points", and the modal itself has zero tests today
EarningsModal mounts: exactly 3, verified (`Calendar.jsx:635`, `MyStocksHub.jsx:445`, `CatalystFlow.jsx:147`) — spec correct. But the section components fan out further: `AnalystPanel`/`OwnershipPanel` are also mounted by `app/src/components/TickerPopup.jsx:215/219` (lazy) and `app/src/pages/charts/widgets/FundamentalsWidget.jsx:256/258` — restyling/replacing them for the modal either forks components or drags two out-of-scope surfaces into P2. Vitest surface (~15 files): `calendar/myStocksHub.test.jsx` (vi.mocks `SentimentGauge`, `CallRecapSection`, and `EarningsModal` **by module path**, :98-108 — any file move breaks the mocks), `calendar/callRecap.test.jsx`, `research/tabs/CallsTab.test.jsx:4-5` (path-mocks both), `CatalystFlow.test.jsx`, `FundamentalsWidget.test.jsx:11-14`, `fundamentals/AnalystPanel.test.jsx` + `OwnershipPanel.test.jsx`, `research/ResearchPage.test.jsx`, `research/tabs/{Estimates,Filings,Financials,Ownership,Ratings}Tab.test.jsx`, `hooks/useResearchOverview.test.js`; calendar feed suites (`CalendarDayTable.test.jsx`, `EarningsCard.test.jsx`) break only if the `row` shape changes. There is **no EarningsModal.test.jsx** (glob: none) — the §8 URL-state/rail tests start from scratch; budget P2 accordingly.

### m3 — Bars store: adequate, but no date-keyed accessor; go through the cached layer

Splits: adjusted daily bars make ratio math safe except a split landing between report close and reaction close (rare; acceptable if noted). Prefer the higher-level cached bars path over raw sqlite so an off-universe calendar name triggers the normal on-demand fetch instead of silently returning zero rows.
