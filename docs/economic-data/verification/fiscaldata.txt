   registry note says Oct 2022). Full history back to 2005-10-03 is covered, no break. The adapter requests ALL
   account types in the window (no server-side label filter), so a date whose label drifts raises MalformedPayload
   instead of silently dropping out; a Closing-Balance row whose close_today_bal becomes non-null and different
   also fails closed.
2. MTS: record_date = report month end; each report carries the current-FY months AND all 12 prior-FY months
   (classification_desc = month name; parent row 'FY yyyy'; Oct-Dec belong to calendar year FY-1). API history
   begins with the 2015-03-31 report, so the first month is 2013-10 (FY2014), not 2015-10. Months are RESTATED in
   later reports for up to ~2 years: 92 of 155 months changed at least once (e.g. 2015-05 82.39B -> 84.07B,
   2015-11 64.55B -> 62.87B). The adapter takes each month from the NEWEST report that carries it. Registry
   revision.type 'minor_routine' (3-period window) would make validate.check_mutation reject those restatements;
   a correction is proposed.
3. SIGN: current_month_dfct_sur_amt is DEFICIT-POSITIVE (Aug 2026 +166.80B = outlays - receipts; April 2026
   surplus = -215.02B; Sep 2025 surplus = -197.94B). Adapter param `sign` (default +1 = provider convention);
   `sign: -1` gives the FRED MTSDS133FMS convention (surplus +, deficit -). A correction is proposed; the
   coordinator decides. USDEFICIT12M (sum of 12) inherits whichever sign is chosen.
